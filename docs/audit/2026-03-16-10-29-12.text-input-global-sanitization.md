## Meaning Of This Change
Numeric input UX now supports text-style entries (including comma separators), while sanitization is centralized and enforced consistently in both state updates and calculation runtime.

## Initial Prompt
`let's go with text as u offered, also make sure input is alwasy sanitized accross the app`

## User-Requested Changes
- Switch number inputs to text input approach.
- Ensure sanitization is consistently applied across the app.

## What Was Implemented
- Added `src/utils/inputSanitization.js` with:
  - `sanitizeInputForKey(key, rawValue, fallbackValue)`
  - `sanitizeAllInputs(rawInputs, fallbackInputs)`
  - comma-aware parsing (`"51,919"` -> `51919`)
  - min/max clamping based on `INPUT_CONSTRAINTS`
- Updated `src/App.jsx`:
  - `handleChange` now sanitizes every incoming value before writing to app state.
- Updated `src/utils/taxEngine.js`:
  - replaced local sanitization logic with shared `sanitizeAllInputs()` utility.
- Updated `src/components/InputPanel.jsx`:
  - editable field changed from `type='number'` to `type='text'` with `inputMode='decimal'`
  - passes raw text to `onChange` for sanitizer parsing.

## Important Technical Details
- Sanitization now exists at two layers:
  - UI/state layer (`App`): prevents unsanitized state propagation.
  - Engine layer (`calculate`): defense-in-depth for direct/function-level calls.
- Invalid text falls back to prior/default numeric value; out-of-range values are clamped.
- Validation checks:
  - `npm run lint` passes.
  - sanitizer smoke test confirms comma parsing and clamping behavior.
